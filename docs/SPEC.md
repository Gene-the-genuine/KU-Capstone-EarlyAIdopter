# AI 기반 상담 회기 기록 및 실천 지원 웹서비스 — MVP 구현 명세 v1.0

## 0. 목표와 전제

- 목적: 상담사가 입력한 회기 텍스트를 AI가 정리하고, 상담사가 검토하여 공유한 결과를 내담자가 복습하며 실천 과제 체크와 다음 회기 준비 메모를 남기는 웹서비스.
- 사용자: 상담사(아이디/비밀번호 회원가입 및 로그인), 내담자(로그인 없이 링크 접속).
- 최우선: 바이브코딩 구현 난도·시간 최소화, 로컬 시연 성공, 이후 Vercel 배포 가능.
- 음성 업로드/STT 없음. 실제 환자/내담자 정보 사용하지 않고 합성 데이터만 시연.
- AI는 상담을 직접 수행하지 않는다. 상담사 승인 전 AI 결과는 내담자에게 보여주지 않는다.
- 서비스 UI와 텍스트는 한국어.

## 1. 확정 기술 스택

- Next.js App Router, TypeScript, Tailwind CSS, shadcn/ui.
- Next.js 자체 서버(Route Handlers 또는 Server Actions); 별도 API 서버 없음.
- Supabase PostgreSQL 및 `@supabase/supabase-js` **서버 전용** DB 호출.
- 로그인: `counselors` 자체 계정 테이블(고유 username + bcryptjs password_hash)과 `iron-session`의 httpOnly 쿠키. Supabase Auth는 **사용하지 않음**. 이 방식은 사용자가 요청한 일반 아이디/비밀번호를 직접 지원하며 시연에 필요한 이메일 인증/SMTP를 피함.
- OpenAI API 서버 측 호출, `OPENAI_MODEL` 환경변수 기반. 안정적인 JSON 구조화 출력 적용(지원되는 모델/SDK 기능 확인 후 구현).
- QR: `qrcode.react`.
- Vercel 배포 지원, 서버 프로세스 메모리/로컬 파일에 영구 데이터 저장하지 않음.
- 비밀번호 해시, 세션 확인, 서버 측 소유권 검사, 공유 토큰 검증 외 운영용 고급 보안/규정 대응은 MVP 제외. **실제 상담정보 처리에 사용하면 안 되는 데모임을 README에 명시.**

## 2. 사용자/접근 정책

### 상담사

- `/login` 로그인: 아이디(username) + 비밀번호. 로그인 성공 시 `/counselor`.
- `/signup` 회원가입: 아이디 + 비밀번호 + 비밀번호 확인. 실제 DB에 계정 생성. 중복 아이디, 불일치, 너무 짧은 비밀번호(최소 8자)만 기본 검증. 이메일, 본인인증 없음.
- 로그아웃 가능. 로그인되지 않았으면 모든 `/counselor/**` 접근 시 `/login`으로 보냄.
- 상담사마다 자기 내담자/회기만 조회·수정 가능. 회원가입된 여러 상담사는 각각 독립 데이터 보유.

### 내담자

- 회원가입/로그인 없음. 랜덤 공유 토큰을 포함한 URL로 접속.
- 공유된 회기 목록 및 공유된 회기 상세만 열람. draft는 노출하지 않음.
- 내담자 홈에 이름과 생년월일 표시, 상담 목적 메모는 표시하지 않음.
- 실천 과제 완료 여부와 질문별 메모는 내담자만 확인·수정. 상담사 페이지/API 응답에 포함하지 않음.
- 링크를 가진 사람은 내담자 화면에 접근할 수 있으므로 합성 데이터 외 사용 금지. 실제 서비스 전환 시 별도 보안 검토 필요.

## 3. 페이지 구조 및 이동

### A. `/login` — 상담사 로그인

- 아이디, 비밀번호, 로그인 버튼, 회원가입 페이지 이동 링크.
- 성공 시 `/counselor`, 실패 시 간단한 오류 메시지.

### B. `/signup` — 상담사 회원가입

- 아이디, 비밀번호, 비밀번호 확인, 가입 버튼, 로그인 이동 링크.
- 가입 성공 시 로그인 페이지 이동(명확한 성공 메시지).

### C. `/counselor` — 상담사 대시보드

- 내담자 목록, 내담자 추가 모달, 내담자 삭제 버튼 및 확인창.
- 내담자 선택 시 이름/생년월일/상담 목적 메모와 해당 내담자의 회기 목록(회기 번호, 날짜, 상태) 표시.
- 내담자별 `새 회기 생성` 버튼. **새 회기 생성은 이곳에서만 제공.**
- 기존 회기 클릭 시 `/counselor/clients/[clientId]/sessions/[sessionId]`로 이동.
- 새 회기 생성 버튼 클릭 시 해당 내담자의 새 독립 회기 레코드를 DB에 draft로 생성하고 해당 URL로 이동. 회기 번호는 내담자 기준 생성순서로 증가, 날짜는 오늘로 초기화하되 변경 가능.
- 회기는 여러 개 동시에 draft일 수 있음. 2회기 draft가 있어도 3회기 생성 가능.
- 회기 삭제 버튼 없음.

### D. `/counselor/clients/[clientId]/sessions/[sessionId]` — 통합 상담사 회기 페이지

- 페이지 상단에 `대시보드로 돌아가기` 버튼.
- DB 상태는 `draft`/`shared` 두 가지. `이전 기록 없음`은 새 회기를 만들어야 함을 알리는 빈 UI 상태일 뿐 회기 DB 상태가 아님. 실제 회기가 없으면 대시보드에 빈 상태와 생성 버튼을 표시.
- draft: 날짜 편집, 상담 원문 textarea, AI 생성/재생성, 상담사용 상세 기록 textarea, 내담자용 요약 textarea, 실천 과제 행 추가/수정/삭제, 준비 질문 행 추가/수정/삭제, 임시 저장, 공유 확정.
- AI 생성 시 현재 입력된 원문만 참고, 기존 회기/과제/메모 정보는 사용하지 않음.
- 최초 생성 후 재생성 시 기존 AI 결과(상담사용 기록/요약/과제/질문)의 수동 수정도 모두 덮어씀. 재생성 전 확인 모달 필수. 취소하면 변경 없음.
- 생성 중 버튼 disabled + 로딩, 실패 시 오류 안내 + 원문/현재 결과 보존 + 다시 시도 버튼. 복잡한 재시도 큐 없음.
- `임시 저장` 버튼은 현재 화면의 모든 draft 내용(날짜, 원문, AI 기록, 배열)을 DB에 저장. 저장 전 화면 이탈 시 미저장 변경 내용은 손실될 수 있음을 안내(브라우저 기본 경고나 간단한 확인창 중 쉬운 방법).
- `공유 확정` 클릭 시 변경된 draft 내용을 원자적으로/일관되게 저장하며 상태를 shared로 변경. 확인 모달 이후 공유 URL/QR 모달 표시.
- shared: 동일 컴포넌트를 읽기 전용으로 렌더. 원문과 상담사용 AI 기록 포함 모든 상담사 데이터 조회 가능, 모든 필드 수정/AI 재생성/저장 불가. `공유 링크 보기` 버튼으로 언제든 링크/QR 재표시.
- 공유 후 상담사 기록은 불변. 내담자의 체크·메모는 별도로 변경 가능.

### E. `/client/[token]` — 내담자 홈

- 내담자 이름, 생년월일, **shared 회기만** 날짜/회기 번호 순으로 목록 표시. 항목 누르면 상세로 이동.
- 토큰 없거나 유효하지 않으면 접근 불가 안내.

### F. `/client/[token]/sessions/[sessionId]` — 내담자 회기 상세

- 직접 링크 접근 시 해당 회기 상세로 이동.
- 내담자용 요약, 과제 체크박스, 다음 상담 준비 질문별 입력 textarea와 메모 저장 버튼.
- 과제 체크/해제 시 즉시 DB 저장. 각 질문의 답변은 `메모 저장` 버튼으로 DB 저장(한 번에 저장).
- 내담자 홈 이동, 이전/다음 공유 완료 회기 이동 버튼. 해당 방향에 회기가 없으면 숨기거나 disabled.
- 상담 원문·상담사용 상세 기록·상담 목적 메모·다른 내담자의 데이터는 절대 응답/노출하지 않음.
- 질문/과제가 없으면 자연스러운 빈 상태 표시.

## 4. 공유 링크 정책

- 내담자별 `share_token`을 최초 내담자 생성 시 무작위 생성하여 고정(내담자마다 하나).
- 각 회기 공유 URL: `/client/{client.share_token}/sessions/{session.id}`.
- 같은 토큰으로 내담자 홈과 모든 **shared** 회기에 접근 가능. 각 회기는 회기 ID로 구별됨.
- QR 코드는 공유 URL을 인코딩. 클립보드 복사 버튼 제공.
- localhost에서 다른 기기로 QR 시연 시 접속 불가할 수 있음. Vercel URL 시연 또는 동일 PC에서 링크 시연 권장. 링크는 `window.location.origin` 기반 절대 URL로 구성하여 배포 환경에서도 동작.
- URL을 가진 사람은 접근 가능하므로 임의의 숫자 ID로 share token을 대체하지 않음.

## 5. 데이터 모델 (필드명은 가능하면 그대로 구현)

- `counselors`: `id uuid PK`, `username text unique`, `password_hash text`, `created_at`.
- `clients`: `id uuid PK`, `counselor_id uuid FK`, `name text`, `birth_date date`, `purpose_note text nullable`, `share_token text unique`, `created_at`.
- `sessions`: `id uuid PK`, `client_id uuid FK`, `session_number int`, `session_date date`, `status text ('draft'|'shared')`, `source_text text default ''`, `counselor_note text default ''`, `client_summary text default ''`, `created_at`, `shared_at nullable`. Unique(`client_id`, `session_number`).
- `action_items`: `id uuid PK`, `session_id uuid FK`, `position int`, `title text`, `is_completed boolean default false`.
- `preparation_questions`: `id uuid PK`, `session_id uuid FK`, `position int`, `question text`, `client_answer text default ''`.
- 내담자 삭제 시 소속 sessions, action_items, preparation_questions가 함께 삭제되도록 FK ON DELETE CASCADE. 회기 삭제 UI/API는 없음.
- DB 스키마 생성/마이그레이션은 하나의 `supabase/schema.sql`에 유지. 초기 개발용 적용 절차를 README에 작성.
- 회기 번호는 내담자별 생성 순서 기준이며 날짜를 바꾸어도 변하지 않음. 동시 생성 충돌 시 유니크 제약 + 간단한 재시도 또는 DB 트랜잭션으로 처리.
- draft 저장 시 과제/질문 배열의 변경을 DB에 동기화한다. shared 후에는 이들의 제목/질문 행 변경 금지, 단 내담자 완료여부/답변만 갱신.

## 6. AI 입력/출력 규칙

### 입력

- 현재 회기의 `source_text` 문자열만 사용. 이전 회기, 생년월일, 상담 목적, 과제 체크/메모는 보내지 않음.
- 원문이 비어 있거나 공백뿐이면 요청하지 않고 안내.

### 출력 JSON

```json
{
  "counselorNote": "원문에 근거한 상담사용 상세 기록",
  "clientSummary": "내담자가 이해하기 쉬운 존댓말 요약",
  "actionItems": ["실제로 합의된 과제1"],
  "preparationQuestions": ["다음 상담 전 생각할 질문1"]
}
```

- `counselorNote`: 원문 근거만 담은 사실 중심 기록. 상담 주제/주요 내용/감정 표현/합의사항을 자연스러운 문단이나 소제목으로 정리. 임상 진단 단정 금지.
- `clientSummary`: 공감적이지만 과장하지 않는 한국어 존댓말. 5문장 내외.
- `actionItems`: 원문에서 상담사와 내담자가 명시적으로 합의한 행동 과제만 추출. 없으면 `[]`. 추측으로 만들지 않음.
- `preparationQuestions`: 현재 회기에서 다룬 주제를 바탕으로 성찰용 개방형 질문 2~3개(적합한 질문이 없으면 빈 배열도 허용). 치료·진단·위험 예측을 하지 않음.
- JSON 파싱/형식 검증 후 화면에 적용. 형식 오류/네트워크 오류는 간단히 표시하고 기존 편집 상태를 유지.
- AI 결과는 상담사가 수정 가능하고, 상담사가 검토 후 공유해야만 내담자에게 보임.
- 생성 응답 자체는 사용자가 `임시 저장`하거나 `공유 확정`할 때 저장됨(추가 자동 저장 금지).

## 7. 핵심 동작 / 예외

- 새 회기 버튼 클릭 때 DB에 빈 draft 레코드 생성. 단순한 `/new` 작성 페이지는 만들지 않음.
- 각 draft 회기는 별도 레코드/URL로 관리. 여러 draft 동시 존재 허용.
- 2회기 draft가 있어도 3회기 생성 가능. 2회기의 AI 재생성은 오직 2회기 데이터만 덮어쓴다.
- draft에서 원문을 수정하면 이미 생성한 AI 출력은 화면에 남아 있지만 다시 생성하기 전까지 자동 갱신하지 않음. 사용자가 검토 후 직접 재생성/공유 판단.
- 공유 시 최소 내담자용 요약 존재 검증. 공유 순간 승인된 콘텐츠를 저장하고 `shared`로 잠금.
- 같은 계정의 중복 공유 요청 시 이미 shared이면 불필요하게 재저장하지 않고 기존 URL 반환.
- 날짜가 다른 회기와 같아도 허용.
- 내담자 삭제는 대시보드에서만 가능하고 확인 모달 필수. 공유 링크도 삭제와 함께 무효화.
- 질문 삭제/수정은 draft에서만 가능. shared 질문별 메모는 내담자만 수정.
- 서버의 모든 상담사 DB 조작은 현재 로그인한 counselor 소유 관계 검증 후 처리.
- 공유 페이지 요청은 `token -> client -> session.client_id`와 `status='shared'`를 함께 검증.
- 입력 및 저장 성공/실패 메시지, 빈 목록, API 오류 시 무난한 UI 제공.

## 8. UI 원칙

- 과도한 애니메이션/차트 없이 심플한 밝은 테마.
- 상담사 대시보드: 좌측 내담자 목록 + 우측 선택한 내담자의 정보/회기 목록 (좁은 화면에서는 세로 배치).
- 상담사 회기 페이지: 상단 회기 정보/상태/뒤로가기, 원문 섹션, AI 결과 섹션, 하단 저장/공유 액션.
- 공유 모달: 공유 URL, 복사 버튼, QR 코드.
- 내담자 페이지는 모바일 우선, 큰 읽기 쉬운 카드형 요약, 과제 체크리스트, 질문별 메모 폼.
- 한국어 안내·오류·빈 상태 문구.

## 9. 범위 제외

- 음성/STT, 상담센터 다중 관리자, 상담 예약, 과제 알림, 채팅, 내담자 로그인, 메일, PDF, 통계 대시보드, 회기 삭제, 공유 후 상담사 기록 수정, 이전 회기 AI 분석, 복잡한 인증/권한 설정, 실제 심리상담 임상 검증.
- 실제 민감정보 데이터 사용, 서비스 공개 운영 및 의료/개인정보 규정 준수 대응.

## 10. MVP 완료 검증 시나리오

1. 아이디/비밀번호로 상담사 회원가입 → 로그인 → 로그아웃 → 재로그인 성공.
2. 내담자 A 생성(이름/생년월일/상담 목적 메모), 내담자 B 생성; 각 상담사 데이터 분리.
3. A의 1회기 생성 → 원문 입력 → AI JSON 생성 → 수동 수정 → 임시 저장 → 새로고침 후 유지.
4. A의 2회기를 생성하고 draft로 둔 채 3회기도 생성; 번호 1/2/3 각자 고유 URL.
5. 2회기 AI 재생성 시 덮어쓰기 확인 모달 등장, 취소 시 보존, 확인 시 2회기 결과만 변경.
6. 1회기 공유 확정 → 링크/QR 표시 → 상담사 페이지 읽기 전용으로 전환.
7. 링크로 접속한 내담자는 A의 이름/생년월일, 1회기 요약/과제/질문만 확인; 원문/상담사용 기록/목적 메모는 볼 수 없음.
8. 내담자가 체크 및 메모 저장 → 새로고침 후 유지. 상담사에게 완료/메모가 보이지 않음.
9. 아직 draft인 2,3회기는 내담자 홈과 이전/다음 회기 이동에 노출되지 않음.
10. 2회기 공유 후 내담자 홈에서 1,2회기를 확인, 이전/다음 이동 성공.
11. 상담사에서 A 삭제 → A의 공유 링크 접근 불가, B는 유지.
12. `npm run build` 통과, `.env.example`/README 존재, Vercel 배포에 필요한 환경변수 설명 존재.
